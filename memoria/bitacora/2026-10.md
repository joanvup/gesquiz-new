## 2026-10-26 — Error de pool MySQL (45028) en producción

- **Objetivo**: explicar y corregir el fallo de login en producción
  `Code: 45028 - pool failed to retrieve a connection from pool (active=0
  idle=0 limit=10)`, que además se mostraba crudo en el navegador.
- **Diagnóstico**:
  - `45028` es `ER_GET_CONNECTION_TIMEOUT` del driver `mariadb`; con
    `active=0 idle=0` nunca se abrió una conexión y la causa real queda en
    `err.cause`, que el mensaje no muestra.
  - Sospechosos: contraseña con caracteres especiales sin codificar en
    `DATABASE_URL`, MySQL 8 con `caching_sha2_password` sin
    `allowPublicKeyRetrieval`, `connectTimeout` por defecto de 1 s, y
    `max_connections` agotado.
- **Cambios**:
  - `src/lib/prisma-adapter.ts`: validación de `DATABASE_URL` con mensajes
    claros (`#`, `?`, `/`, `%` inválido), `parseDatabaseUrl` exportado,
    `connectionLimit`/`connectTimeout`/`acquireTimeout` configurables
    (`DB_POOL_LIMIT`, `DB_CONNECT_TIMEOUT_MS`, `DB_ACQUIRE_TIMEOUT_MS`),
    `allowPublicKeyRetrieval: true` y TLS opcional (`DB_SSL`).
  - `src/lib/db.ts`: el `PrismaClient` se cachea en `globalThis` también en
    producción para no duplicar pools.
  - `src/app/api/auth/login/route.ts`: registra el error real (y su `cause`)
    en el log y responde 503/500 genéricos; ya no expone mensajes de Prisma.
  - `scripts/check-db.ts` + `npm run db:check`: diagnóstico de conexión que
    imprime host/usuario/BD (nunca la contraseña) y el código de error real.
  - `docs/instalacion_produccion.md` §18: causas y solución de este error.
- **Archivos**: los anteriores + `src/__tests__/prisma-adapter.test.ts`,
  `package.json`, `memoria/contexto.md`.
- **Pendientes**:
  - Ejecutar `npm run db:check` en el servidor para confirmar la causa exacta
    (MySQL local del equipo de desarrollo está detenido: `seed.test` falla).
  - Revisar si el resto de rutas API siguen devolviendo `err.message` crudo.
- **Commit**: `fix(db): harden MySQL pool config and stop leaking DB errors on login`.
